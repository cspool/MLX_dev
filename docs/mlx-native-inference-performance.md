## 用户新增对照：端到端与串行事件流的差异

需要区分三个量：

| 量 | 获取方式 | 可说明什么 |
| --- | --- | --- |
| 实际串行执行周期 | 完整模型真的在串行周期模拟器运行，各算子实际事件区间相加 | 已执行的串行基线，含该实现的访存/等待成本 |
| 实际端到端周期 | 完整模型在共享阵列、依赖事件和配对调度下完成的全局时钟 | 包含真实重叠、依赖等待、共享资源竞争及本地模板配置 |
| 端到端日志的节点驻留时长总和 | 对同一次并发执行的各节点`publish-start`求和 | 含重叠、驻留等待；不能当作“关闭并发后的真实耗时” |

对照程序为`scripts.compare_mlx_execution_performance`。只接受完整终态，核对相同模型/权重/输入、完整数值程序及内存配置，重新审计双方所有源、参数、输出和资源排空。报告总周期差、串行/端到端周期比、物理请求数、设备输出就绪时间，以及节点区间的总和/并集。实际输出必须一致，不能注入串行/参考中间值。没有完整终态时不产生加速比或外推结果。

当前已核对：正在运行的完整Llama2原生配对程序去除唯一新增的`block_pipeline_plan`后，与已完成串行程序完全相同。配对结果尚未结束，因此性能差异仍待终态。实现差异包括共享阵列与模板配置成本，最终差额不能全部归因于重叠。

完整BERT也按同一清单运行两种周期路径。`bert-qa-physical-full-001`与`bert-qa-paired-full-001`因组件默认的10,000,000周期窗口上限退出1，失败记录保留；后续`002`显式使用完整模型窗口上限10^12、全图上限10^13，不改变资源、模型、数值程序或误差条件。两者以已完成的完整C++微程序结果为运行前数值基准；保留全部三组28/64/64-token输入、12层和199个参数张量，并要求周期执行的实际双logits与微程序结果逐位一致。两次周期运行尚待终态，不能将微程序的宿主耗时当作周期模拟性能。
