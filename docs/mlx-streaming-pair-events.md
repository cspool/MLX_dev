# C++ 流式配对事件与注册访存协议

此增量将现有原生 `CompletionWindow` 逻辑复用到紧凑事件调度器，使消费者可以在整个生产者结束之前消费已完成块。它不是把配对程序替换为整源屏障，也不新增硬件 opcode。完整目录到此接口的直接链接和整模执行仍未完成。

## 配对契约

compact `source_streams` 可提供 `streaming_pairs`。每项绑定 producer_source、consumer_source、逻辑输出 mapping 和 1..32 个 event_slots。参与源还必须提供实际 operator_kind、output_shape、output_dtype。

生产者必须为矩阵／向量源且只有该消费者；消费者必须为同输出 shape 的逐元素向量源。拒绝重复／交叠配对、错误 batch／块数、缺失 dtype、资源不足和不支持的消费者。矩阵、普通向量、mean 与 softmax 生产者分别按原生映射确定消费者需要哪些生产者块。

- 其他输入依赖均满足、阵列空闲且有两个前端槽后，配对两源共同启动。配对期间无关阵列源等待，但控制／搬运源仍可并行。
- 两角色各自每 PE 至多一个上下文。消费者总驻留上限为 `min(PE数量, floor((128 - 生产者SPM需求)/消费者SPM需求))`；并同时检查 RF、ROM 和上下文容量。这是当前原生闭合配对 profile 的保留规则，不推广为任意 GPU 调度规则。
- 生产者准入需要有限完成槽 credit；消费者可以先驻留，但所需生产者块未可见时不能发射。依赖集合按逻辑输出范围确定，不按宿主槽号判断。
- 每组使用独立 epoch，完成通知绑定块与 lease。每个块的输出事务宽度和总写入量必须符合 shape/dtype；生产者最后完成必须来自最终 DMA 写响应。完成下一边沿才可见。
- 完成前缀可以释放事件记录，但不意味着输出数据可以提前释放。事件模型不执行 Tensor 存储；完整链接时仍须保留数据缓冲到实际消费者结束。

这复用了原生 `model_events/completion_window.cc`，没有修改该冻结源码。配对组完成后，完成窗口必须排空，阵列资源释放，下一配对使用新 epoch。

## 注册访存不是直接端点延迟

首轮对照暴露出实际 `PhysicalMemory`／`QueuedPhysicalPort` 的提交与接收边界：请求在 S 拍提交，最早 S+1 拍被接受。若接收周期为 A、服务延迟为 L，则无重试时最早响应为：

`accept = ceil((S+1)/A) × A`，`response = accept + L`。

响应还可能等待前端响应节拍或 SPM 写口，通路在消费后的下一边沿才能复用。因此新增显式 `physical_memory` profile，而不是调整原生测量值拟合误差。它覆盖注册队列＋固定延迟、accept_period、单事务共享通路；当前只支持 nack_every=0，不支持缓存时序或重试，其他策略明确拒绝。

此前独立窗口使用的直接 TensorMemoryPort profile 保留不变。测试还用服务延迟 1/3、接收周期 2/4、前端 dma_latency=101 和不同请求／响应节拍证明外部端点正确覆盖前端直接服务假设。

## 验证与证据边界

`streaming-event-regression-002`：406 项回归通过。`streaming-event-safety-001`：401 次 ASan/UBSan/LSan 重放通过（329 正常、72 预期拒绝）。

`streaming-pair-alignment-001` 独立重跑 25 个实际数值案例，包括：

- FP16/FP32 矩阵→rsqrt，完成槽 1/2/32，模板编程开／关。
- 广播 matmul 的两个 batch、普通向量、mean／softmax 生产者。
- 非默认物理接收节拍和前端响应节拍。
- 16 PE 的 F32 生产者保留，消费者上限 11，避免消费者占满 SPM 阻止生产者继续。

原生 C++ 路径实际计算结果并完成后续 token 选择；数值与测试数学参考核对，独立重放输出逐字节一致。事件路径比较的是**配对组开始至结束**，不含其后的 argmax／最终读回。25 例配对周期、源发布、完成窗口状态一致；回归另核对 RF/SPM/ROM 峰值和各计算／SFU／SPM／DMA 在途时间。全局跨源重叠不能简单用各源局部重叠计数相加。

独立 trace 审计按另一份索引公式重新计算消费者依赖，检查其发射不早于所有所需生产者写完成可见边沿。另有连续 epoch、阵列独占与控制源并行，以及错误 shape/dtype、写入量不足、非写响应结束、槽数超限、资源不足和交叠配对拒绝检查。

历史失败保留：tests-001 的时序差异来自遗漏注册队列阶段；tests-002 的两例 batch token 检查使用了错误的嵌套列表形状，修正检查器的展平口径后通过。没有降低数值合约或省略工作。

## 接下来

`model_streaming_pair_events.py` 目前是一个隔离配对验证适配器，要求外部输入已经是资产；不能拿它跳过完整模型中的真实父依赖。后续完整链接器须从 BERT/Llama2 目录直接建立全部源／batch／run／模板和原配对关系，保留控制见证、实际地址和缓冲生命期，并接入最终读回及 CPU 后处理边界。

此增量不证明完整模型、完整论文 CDC／NoC 或 Chipyard 系统通过。六个整模任务仍分别验收；Chipyard 优先，GPU 后置，RTL/PPA 最后。
