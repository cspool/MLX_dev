# 紧凑块运行段与 C++ 活动窗口游标

本增量使 C++ 不再为紧凑输入预先创建全部块对象。源／窗口／运行段、PE 空间映射和块内指令循环分别表示，对应[联合设计契约](mlx-isa-spatial-scheduling-contract.md)；它是模拟器表示与调度实现，不是新增硬件 opcode。

## 可执行表示

schema v6 的 `source_streams` 与显式 `blocks/controllers/source_graph` 互斥，要求已有的摘要绑定事件模式和按源调度。每个源保留 `source_operator_id`、`family`、`parents`、顺序 `windows`。窗口中每个 run 保存完整 count 与 event_pattern；阵列 run 另给 template、pe_base、pe_stride。

第 i 个实例映射到 `(pe_base + i × pe_stride) % PE_count`。模式切换、尾块或映射规律改变时分段，不能裁剪实例或把尾块混进完整块。阶段内部的 K 循环仍在原事件模式中，不因块运行段压缩而减少。

C++ 为每个活动源窗口最多生成一个下一待准入候选。块成功准入后才生成其后继候选；当前窗口全部退休后才开始下一窗口。尚未启动的源不创建块对象。逻辑 ID 根据源、窗口和块序号生成，内部键来自固定逻辑序号区间；删除／重建宿主对象不会改变发射和完成优先级。

退休后先完成事件、ROM 引用、源／窗口发布等处理，再删除宿主块对象。当前保留量受 PE 上下文、活动前端数量和少量待准入对象约束，并有运行期上限检查；源／窗口／run 元数据仍保留，但不随重复实例数展开。旧显式输入路径保持原表示以供对照。

## 完整工作与有界记录

总逻辑块数和动态事件数由所有 run 与模式计数计算，使用检查过的加法／乘法。每块生成、准入、执行和退休仍实际发生；最终核对全部动态事件完成、源图完成及块／事件／ROM 记录排空。当前逻辑块 ID 上限仍为 INT32_MAX，超限明确拒绝。

`block_interval_limit` 只限制退休历史记录，不限制执行。保存的是最先退休的有限记录，输出按逻辑 ID 排序；不足全部历史时设置 `block_intervals_truncated`。事件 trace 仍另有显式上限。不能根据有限日志条数推断只有这些块执行，也不能用有限日志单独声称完成了逐事件外部审计。

`model_compact_event_streams.py` 提供由既有已展开测试图到运行段的转换，以及有界审计展开。真正 C++ 执行不调用审计展开函数。完整模型目录到运行段的直接生成器仍待接入，不能先构造 1,313 万块 JSON 再称其为按需装入。

## 验证

`compact-block-regression-003`：369 项回归通过。新增 25 项覆盖实际依赖图对应的预展开／紧凑结果一致、源批次、私有控制与 view、定时 ROM、PE 循环映射与尾段、历史记录上限以及非法 count／域／父依赖拒绝。

`compact-block-safety-001`：364 次 ASan/UBSan/LSan 重放通过（303 正常、61 预期拒绝）。不截断工作：

- 10 万个逻辑块由一个 run 表示，全部执行，目标周期 100,001，活动／待准入块描述符峰值不超过 3。
- 十亿块输入能直接开始执行并触发明确的周期预算退出，没有预先创建十亿对象。这是受限运行，不是十亿块完成证据。
- 对日志完整的用例，独立审计展开与原模式重建，核对依赖、端口、驻留与实例；截断日志压力项检查声明总量、实际完成计数、源／窗口边界与排空，不声称拥有完整外部 trace。

## 来自完整 BERT 编译目录的窗口

`bert-full-shape-compact-pattern-001` 使用 F32 div `[1,64,3072]`，原始、预展开、只懒解析、紧凑块四条路径正常结束。12,288 个逻辑块压为 1 个 run，活动／待准入描述符峰值 26；其中宿主待准入对象不等于新增硬件上下文。

四条路径均处理 724,992 个动态事件，目标周期均为 5,308,485；硬件资源、工作计数和源完成边界一致。紧凑路径不保存块退休历史，仍完成全部工作。单次宿主耗时约 35.19／34.75／34.00／33.59 秒，保留为观察值，不宣称稳定速度提升或目标硬件性能变化。

这只是一个完整尺寸事件窗口，不计算 Tensor 值，不是完整模型或 Chipyard 验收，也不是整模性能误差。
