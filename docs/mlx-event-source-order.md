# 并发源执行顺序与事件窗口组对照

本增量把原生共享阵列的逻辑源仲裁顺序引入 C++ 事件模型，并用实际矩阵/向量并发数值执行核对。它补齐跨源组合的一项必要规则，**不是完整源图或整模误差结果**。Chipyard 整模验收仍优先，GPU 新实验等待，RTL/PPA 最后。

## 为什么不能只组合单窗口周期

原生 `ready_graph` 按逻辑源次序调用各前端的 tick；每个阵列前端先检查本源 SPM、DMA、计算/SFU 完成，再选择本源的新指令和 DMA。下一源随后才能检查／声明共享端口。服务资源与数据在规定的下一边沿可见，不能同周期跨源提前复用。

旧事件模式先处理所有源的完成，再统一发射。这会让高编号源的完成先于低编号源的新访存声明端口，或让高编号源的 SPM 完成抢占低编号源的算术写回。即使每个独立窗口周期正确，合并后也可能不同。

schema v6 新增显式 `source_tick_order=true`：按逻辑源顺序处理该源到期完成，再进行该源发射；退休释放和模板边沿仍独立处理。循环只遍历当前活跃源及到期事件，不改成逐周期 Python 循环。旧模式默认不变，作为已命名的历史对照；本模式暂只支持 `source_priority`，拒绝把全局 round_robin 混标为原生顺序。

## 完整窗口组与真实数值执行

`src/mlxsim/model_array_group_events.py` 组合 2..32 个独立完整矩阵／向量窗口，保留所有块和循环、源次序与事件身份，核对共同硬件、端口、延迟及 SFU 发射间隔。输入不是原生测得持续时间。相同原生模板 key 与机器字共享 ROM，不因源不同而重复计费；若同一机器字的上下文容量需求不同，当前接口明确拒绝，等待代码身份与容量描述进一步解耦。

`simulator_ext/event_alignment` 使用未修改的原生 matrix/vector 前端及同一 `shared_array::Resources`，按源次序真正计算各窗口。它使用各窗口的固定延迟 TensorMemoryPort，但阵列 DMA 服务槽全局互斥，不创造多条同时工作的 DMA 通路。数值输出与独立完整窗口执行逐字节一致。没有注入参考中间数据，没有修改运行中整模来源。

这里尚不包含控制／搬运前端与 PE 的整图混合、batch 切换、SSA 发布、动态见证、streaming pair 或模板编程／cache 时序。支持 2..32 个输入是接口范围，本次实际数值证据是双源，不冒称已验证所有源数量。

## 本次观察到的误差

`array-group-event-alignment-001` 独立重跑 32 组：matrix/matrix、matrix/vector、vector/matrix、vector/vector；FP16/FP32；1 或 2 个 PE；默认或非默认端口周期/固定内存延迟。两种事件模式和原生路径均保留并发。

| 对照 | 结果 |
| --- | --- |
| 新按源推进 vs 原生并发数值执行 | 32/32 组总周期及各源完成周期一致 |
| 旧全局完成优先 vs 同一原生执行 | 9/32 组周期不同，最大绝对相对误差 2.631084% |
| 最大差异案例 | 原生 5,321 周期，旧事件 5,181 周期，有符号误差 −2.631084% |

误差分母是同组原生执行周期，**不是 GPU 实测、宿主秒数或整模推理时间**。块准入／退休边沿、RF/SPM/ROM/上下文峰值和工作字节也对齐。不同仲裁造成端口等待和重叠变化，可使旧预测偏高或偏低，不宜用统一缩放常数补偿。

累计 `event-source-order-regression-001` 261 项回归通过；`event-source-order-safety-001` 272 次 ASan/UBSan/LSan 重放（236 正常、36 预期拒绝）。此前 22 个矩阵、48 个向量、18 个搬运和 28 个控制窗口在新引擎下重新对照，旧 schema/模式结果保留。

独立审计入口 `scripts.verify_mlx_array_group_alignment` 保存真实输出、原生与两种事件报告、输入及来源摘要。归档保留模板共享和非共享资源峰值，不仅核对总周期。`full_model_event_lowering_complete=false`，模型级性能误差仍不可用。
