# MLX 主线验收与执行优先级

2026-09-09 按用户最新要求更新。本页规定当前顺序；不把历史组件证书或运行中的状态改记为整模通过。

## P0：五项主线任务最高优先级

当前首先集中处理 **Chipyard 整模系统验收**。其余四项同属 P0，按依赖推进；GPU 新实验等待 P0 验收，RTL/PPA 更后置。

| 工作 | 已有证据 | 仍需满足的退出条件 |
| --- | --- | --- |
| 完整模型主要正确性 | 公开 dense Llama2 原生完整执行；BERT QA 原生微程序完整执行 | 每种待验收实现分别完成完整参数、算子路由、真实中间数据和最终任务结果审计；原生结果不能转移给配对版本、Chipyard 或作者 hybrid |
| MLX 并发端到端 | 原生 Llama2/BERT 配对整模运行仍在执行 | 独立终态、完整源/降级步骤覆盖、输出与数值合约、真实 token/cache 或 QA 后处理、资源和访存排空 |
| MLX 并发事件驱动 | 320 项回归通过，未改动的事件核心保留 291 次安全重放；BERT 3,838 个窗口全部编译并绑定真实布尔见证，Llama2 12,127/12,133 个窗口已编译；仍未整模事件执行 | C++ 按需装入与实例资源绑定，补齐 Llama2 分支、实际 batch 地址和流式块事件，统一物理访存／模板／最终读回边界；完成整模事件覆盖及误差核对 |
| MLX 两模型性能误差 | 尚无完整模型结果 | 两条并发路径使用相同模型、输入、算子路由、硬件资源和计时边界；计算 `(C_event-C_e2e)/C_e2e`，分析有效并发、资源利用、调度和等待差异 |
| Chipyard 系统集成 | 登记小负载已通过；两个完整 Llama2 及一个完整 BERT 配对 Rocket 尝试仍在运行，未有终态 | 实际完整 CPU/RoCC/HellaCache 路径终态、所有任务/输出/反馈核对、来源与二进制审计通过；BERT 新系统图 ABI 已补齐，但不能用原生 QA 或小图结果代替整模验收 |

合理的框架/GPU 浮点差异按预先声明的数值合约记录，不要求逐位匹配 GPU，也不覆盖旧失败记录。缺算子、未计算输出、错误控制/反馈和不完整执行不属于可容忍误差。

## 当前 Chipyard 推进内容

1. 保留两个已启动完整尝试的程序、来源、二进制和运行记录，持续检查实际进展与终态。宿主运行时间或算子编号不能充当模型完成率。
2. 定位完整运行过慢的宿主原因。[独立预检的统计采样](mlx-chipyard-host-overhead.md)已确认热点主要在 Verilator 生成代码；设备及内存报告与未采样原预检逐字节一致。该预检不是完整模型热点证明，也不是目标性能测量。
3. 在独立输出目录测试生成 C++ 的宿主编译优化，保持同一生成代码、CPU/缓存/设备配置、断言和周期规则。已核对末尾 `-Os` 覆盖前面的 `-O3`，但独立 `-O3` 重编译虽通过预检等价，本次宿主耗时反而增加，因此不采用、不替换运行中的二进制。整模运行过慢仍未解决。
4. 系统 BERT 的[现代整图接口](mlx-modern-system-graph.md)已补齐 source-group、tuple/split 生命周期、QA 实际 CPU 输出及向量描述符。两个配对 Rocket 小图与独立审计通过，完整 1,141 源/3,046 步骤/693 配对的 BERT 系统尝试已启动；尚无完整终态，不能转移原生或小图的结论。

不以缩小模型外推、串行事件总和或功能快路径代替完整并发端到端系统模拟。若采用不同 CPU/缓存时序抽象，必须作为新系统模型明确命名和验证，不能仍称原 Rocket 周期路径已经通过。

## P1 与 P2

- **P1：GPU 实机与模拟器实验。** 已完成的 RTX4090 整模实测保留；RTX5090 的已有组件探针保留原始记录，不扩展新实验、不视作整模 GPU 模拟验收。正式 GPU 误差是匹配架构模拟器相对实机的误差，与 MLX 两种模拟方式的误差分开。
- **P2：对应 RTL 与 PPA。** 优先级低于 GPU 实机和模拟器，当前不推进。不因 Chipyard 使用现有 RTL 仿真就提前修改 MLX 电路。

所有架构比较和消融保留各自并发能力；并发效率、资源利用与调度效率用于解释性能，不把占用率直接等同于有效工作比例。
