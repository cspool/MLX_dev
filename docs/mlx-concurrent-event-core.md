# C++并发事件核心与完整模型资源接口

这是独立事件驱动路径的首个实现增量，不是完整模型的事件模拟结果。目标仍是比较**保留并发的MLX事件模型与端到端执行模型**，不能用串行对照替代，也不把本组件与RTX4090实机时间直接相除。

优先级：本工作属于MLX主线，与完整正确性、并发端到端及Chipyard整模验收同列最高；当前先集中处理Chipyard整模验收。GPU新增实验等待该主线验收，RTL/PPA最后。事件循环与全模型lowering尚待实现，不因核心组件通过而抢先宣布整模通过。

## 已实现

`simulator_ext/event_schedule`提供原生C++可执行程序`mlx-event-schedule`。输入是显式事件/依赖及资源描述，事件日历按完成、退休、模板写入和端口再次可用的时刻推进，不执行Python周期循环。支持：

- 固定PE映射下的动态块准入；每PE至多2上下文、16个RF向量、32个ROM word，全阵列128个SPM向量，均不自动扩容。
- RF/SPM连续区域分配、相同模板的驻留ROM共享、按字模拟模板编程占用发射端口、退休回收。
- 每块单frontier和一条在途事件；同PE不同上下文可以在不同服务单元重叠，多PE并行；DMA/SPM端口为有限共享资源。
- 事件完成结果下一边沿可见；资源占用持续到释放边界，拒绝依赖环、资源驻留死锁、未知事件类型和周期越界。
- `source_priority`与`round_robin`只改变候选选择，保留相同PE、上下文和服务资源；不是通过关闭并发制造消融。
- 按区间积分的驻留、依赖等待、模板等待、服务/发射等待、FU/SPM/DMA忙碌、计算/搬运重叠，以及RF/SPM/ROM驻留量。单位和容量×时间分母显式输出。

调度仅扫描在驻留集合内的frontier；待准入块按source/PE/template分组，容量变化时检查组头，不在每个事件上扫描全部未来块。4096个映射块的检查保留所有实例：在配置1024-cycle服务延迟的组件中，模拟时间1,049,600周期，实际日历处理8192个完成/退休记录，而不是推进一百万次时钟。该数字只证明日历机制和完整实例计数，不是模型推理性能。

事件目前是**时序IR**：模板机器字用于身份与ROM容量，不在本核心重新计算Tensor数值。`declared_work`的有效lane/字节来自输入声明，不冒充真实数值执行计数。事件模型不输出logits，始终标记`tensor_values_executed=false`、`full_model_verified=false`和`inference_performance_eligible=false`。

## 完整程序资源检查

`src/mlxsim/model_event_resources.py`从实际完整编译程序提取全部源身份、实际矩阵/向量模板、PE几何、RF/SPM/ROM需求及块数，拒绝串行配置、资源扩容或matrix/vector配置不一致。已处理完整Llama2的6181个源节点，以及BERT的1141个源调用/3046个降级步骤；memory/control源也保留为待接入项，不丢弃。

| 当前矩阵模板 | RF向量/上下文 | SPM向量/上下文 | 仅考虑同类模板的全阵列驻留上限 |
| --- | ---: | ---: | ---: |
| FP16，2×16输出、K块64 | 6 | 37 | 3 |
| FP32，2×16输出、K块64 | 6 | 73 | 1 |

上限来自实际编译器的`spm_bytes_used`与全阵列128-vector容量；尚未扣除其他同时驻留的算子和碎片。**它是当前分块/缓冲方案的限制，不代表MLX架构本身只能使用1个或3个PE。** 改变分块可能改善驻留，也会改变访存/复用，需在两种模型中同步修改并验证，不能只改变事件估计中的峰值吞吐。

资源文件不包含预测周期，明确`full_event_lowering_complete=false`、`event_simulated_cycles=null`、`performance_error_available=false`。这避免将“完整资源清单已提取”误标为“完整事件模型已运行”。

## 验证及下一阶段

最新[完整控制窗口事件路径](mlx-control-event-lowering.md)提供 schema v6 的独立 RV64 叶程序资源域、所有动态指令和数据相关选择见证；28 个实际控制窗口对齐。累计 221 项回归、202 次安全重放通过；四类窗口已覆盖，但完整源图、动态见证接入、跨源仲裁和整模误差仍未完成。

最新[独立搬运控制器事件路径](mlx-memory-event-lowering.md)提供 schema v5 的私有转换/staging 和共享总线竞争；18 个实际搬运窗口与事件周期/流量对齐，旧矩阵/向量对照保留。累计 176 项回归、166 次安全重放通过。完整控制、跨源时序和整图仍待接入，不能报告模型级误差。

最新[完整向量窗口事件路径](mlx-vector-event-lowering.md)已接入逐元素、mean/softmax 归约和操作数准备流程；48 个向量窗口与原生执行一致，旧矩阵对照保留。148 项回归及 142 次安全重放通过；独立搬运、控制、跨源与整图接入仍待完成。

最新[端口契约与完整矩阵窗口](mlx-event-port-contract.md)增量提供 schema v3 的独立 DMA 发射、SPM/RF 写回竞争、谓词和准入节拍，并接入 canonical 矩阵微程序循环。22 个窗口与真实数值执行的周期/工作/在途计数一致；95 项回归、94 次安全重放通过。跨源顺序与完整图仍未对齐，不能报告整模误差。

后续已增加[嵌套循环 IR 与按需实例遍历](mlx-event-loop-ir.md)：55 项回归和 58 个安全重放通过，完整工作量不预展开为大量描述符。它沿用 v1 服务模型，尚未完成原生微程序/端口对齐和整模 lowering；不能将此增量作为完整模型事件预测。

组件检查覆盖多PE、同PE不同流水线、共享DMA竞争、下一边沿可见性、ROM共享/耗尽、真实矩阵模板资源需求、4096块、不改变并发的策略消融，以及无效输入拒绝。安全重放另核对实际trace的服务区间、发射带宽、依赖、驻留积分及重叠，且与release完整报告一致。验收数量与摘要以发布清单为准。

[本次归档](../artifacts/tagged/event-core-publication-001/manifest.json)：35项回归通过，29次ASan/UBSan/LSan重放通过（18正常、11预期拒绝）。这只验收上述事件核心和资源接口，不放行完整模型事件误差或系统结果。

完整模型接入仍需：

1. 从真实matrix/vector微程序生成完整循环、尾部lane、SPM访问和DMA事件；以可重放循环表示保留所有实例，不能裁剪wave或把整模型时间反向填进事件。
2. 接入memory计划及RV64控制路径，处理数据相关索引/predicate、guard、tuple/alias生命周期，而不是跳过这些源节点。
3. 接入当前闭合block-pair完成/可见性事件和同一访存配置，再对齐实际端到端的工作量、资源和策略。
4. 先在完整程序上验证事件覆盖，再报告`(C_event-C_e2e)/C_e2e`及内部计数差异。当前还不能产生这一完整模型误差。

没有修改冻结的五个完整端到端运行，也没有修改RTL。既有Python aggregate surrogate与DSAGEN历史配置不能直接代替该完整资源约束接口。
