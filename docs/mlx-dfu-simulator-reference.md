## 多周期推进对当前问题的意义

现有 Chipyard 小负载宿主采样热点主要在 Verilator 生成代码；单改宿主 `-O3` 没有获得加速。因此 D017 的两种推进模式值得沿实际实现继续核对，而不是继续把编译器选项当作已解决的加速方案。

MLX 若增加合并推进，必须明确区间边界及不能合并的条件：潜在 CPU/设备交互、下一次访存响应、依赖可见性、共享资源释放、模板写入、故障和中断等。正确性比较应覆盖真实输出、工作实例、请求/响应、完成事件和资源守恒；相同精确模式要求目标周期一致，近似模式则单独量化误差。宿主运行更快不等于目标硬件性能更高。

这是后续实现要求，不是当前已实现能力。真实 Rocket 周期路径、原生 C++ 数据执行和独立事件模型仍分别命名、分别验收；其他系统抽象不得替代未通过的 Chipyard 整模结果。
