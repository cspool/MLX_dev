# PE本地模板装载时序

独立分支`mlx-shared-array-v1`为共享阵列增加显式的本地模板装载模式。它模拟已解码描述符中的指令字如何进入PE的真实32-word模板存储，不修改RTL，也不把主机/cache描述符取回时间包含在此阶段内。

## 时钟与资源规则

- 新模板准入时预留原有ROM范围、RF/SPM和上下文；指令字不立即全部可执行。
- 每个PE每个允许的配置边沿最多写一个模板字，不同PE可以并行。`template_word_period`约束写入节拍，旧模板优先完成。
- 一个PE写模板的周期不接受新的程序发射。已经发射的计算/写回仍按照自己的资源与延迟完成，不能把配置忙周期全部当成损失的计算机会。
- 最后一个模板字写入之后，模板在下一边沿才可用；未就绪模板不能读指令、发射、占用执行服务或提前退休。
- 相同解码域和指令内容共享已装载的模板；引用结束后ROM范围才能回收。新模板复用地址时必须重新装载，不能读到旧内容。

矩阵/向量上下文分别记录`wait_template`和`template_ready`，依赖事件等待与模板等待不混为一种停顿。模板装载继续占用实际上下文和存储预算，不增加额外的32-word副本。

## 计数与边界

报告分别记录实际模板请求/写入字数、配置wall-cycle、配置PE-cycle及待写字数。多个PE同周期写入时，PE-cycle可以大于wall-cycle，二者不能混加。可选的逐字trace包含PE、模板身份、ROM地址、实际字值和完成可见边沿；关闭trace不改变装载或执行。

启用后`template_configuration_cycles_modeled=true`只表示**本地PE编程阶段**已计时。描述符的主机传输、cache读取、RoCC配置命令与新事件ABI仍是另一层工作，不能因此声明完整系统装载或模型性能已验证。

## 验证

[template-loading-001](../artifacts/tagged/template-loading-001/report.json)绑定224项回归及9个ASan/UBSan/LSan执行重放：

- 实际ROM字值、最后一字的下一边沿可见性、配置与发射冲突。
- 模板共享、地址回收/重新装载和错误/过期访问拒绝。
- FP16/FP32、1/3/7周期装载节拍，多PE并行写入。
- 有/无模板trace完全相同的目标事件/周期，以及计时/未计时模式相同的数值和算量。

开发首个契约测试把旧租约跨客户端访问错误的诊断顺序写错，后来改为直接核对旧租约失效；没有放宽模板可见性或访问规则。

## 使用

在`mlx-ready-graph`的options中显式设置：

```json
{
  "template_load_timing": true,
  "template_word_period": 1,
  "template_trace_limit": 100000
}
```

该模式可与`tile_pipeline=true`合用。默认关闭，以保留已登记旧入口的行为；开启后的结果有自己的来源、配置和周期记录，不能重新贴到正在运行的旧版本上。

完整Llama2仍仅做了同一6181节点/873分组程序的1周期限额启动核对，没有完整推理结果。实际系统ABI、一般CDC、全部模型/输入正确性、推理性能与RTL验收仍未完成。
