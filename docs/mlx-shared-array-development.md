# 跨算子共享阵列开发（独立工作树）

基于`aae1524`，分支`mlx-shared-array-v1`。主工作树的完整原生运行70284和Rocket运行91280继续冻结；本分支的修改不作为它们实际执行的实现版本。

目标是把矩阵和向量周期模型中各自独立的RF/SPM、程序容量、发射/写回端口和FU占用，接到同一组真实存储与有界资源。不能让每个算子实例都拥有一份128-vector SPM和完整PE RF，再只在报告中相加或限制计数。

实现约束：

- 每PE共16个64-byte向量寄存器、最多2个驻留上下文、32个指令字；全阵列共128个SPM向量。矩阵6-RF-vector帧和向量8-vector帧通过实际分区共存，不能按各自的slot乘帧宽度而互相覆盖。
- 指令模板按实际内容与解码域共享/分配；不同模板同时驻留时总ROM占用不超过32字。模板引用、RF及SPM在对应上下文输出完成、在途状态解除之后回收。
- 每PE共享一次指令选择和一次RF写回；普通向量FU由矩阵和向量共同使用，SFU独立。SPM服务槽/访问端口、DMA在途槽为全阵列共享。保留当前单在途服务能力，不借机增加吞吐或存储容量。
- 驱动器按显式逻辑源优先级调用客户端；共享资源仲裁记录实际接受者。同一周期释放的资源到下一边沿才能复用，不能由C++调用先后引入零周期交接。
- 每个客户端、上下文租约和在途操作保持独立身份。共享物理端口的响应只由当前DMA所有者接收，不削弱原AddressSpacePort的请求归属检查。
- 首先保持单客户端的原有输出/事件/周期，再验证真正共用存储的矩阵/向量并发、冲突、回压、退休和重用。之后才接完整图和跨算子数据依赖；单独资源组件或独立算子并发不算完整CDC/模型通过。

这仍是C++模拟器改造，不是RTL设计。完整模型与多输入正确性、系统同步和跨算子编译映射未完成前，性能和RTL门槛不变。

## 本轮实现与验证

`simulator_ext/shared_array/`保存唯一的RF、SPM和实际指令字，矩阵/向量前端已删除自己的整阵列数据副本，通过带身份的租约访问真实分区。不同模板同时占用同一PE的实际32-word预算，相同解码域/指令内容可共享模板。两种前端共同仲裁单次发射、RF写回、普通FU、SFU、SPM服务及DMA在途槽；释放在`end_cycle`生效。失败客户端不会把仍持有的资源直接交给其他客户端，阵列会进入拒绝继续执行的错误状态。

前端默认拥有私有的单客户端资源域以保留原调用接口；显式传入同一个`Resources`才进入跨算子共享模式。新`simulator_ext/shared_schedule/`中的C++驱动器在同一Arena、PhysicalMemory、请求身份空间和单调时钟上实际执行矩阵与向量，所有操作数/输出仍是无本地数据指针的虚拟Tensor。它验证独立算子的共享执行，不是完整图调度器。

[正式证据](../artifacts/tagged/shared-array-001/report.json)：

- 158项组件、张量和共享物理执行回归通过。
- 14组旧可执行文件与新可执行文件的比较，全部数值字节及完整JSON事件/周期/资源计数一致；报告记录实际比较的二进制摘要。旧二进制没有在本轮重新构建，不额外扩大它的源码证明范围。
- 14个混合、反压/重试、全局周期/II和ROM容量用例通过ASan/UBSan/LSan，输出和完整目标报告与release一致。
- 同一PE中矩阵6-vector与向量8-vector帧真正同时驻留，RF地址互不重叠，共占14/16向量；后来两个向量上下文可以合法占满16向量，故不能把全程RF峰值固定为14。跨前端的实际issue–complete/DMA响应区间有交叠；共同FU/端口不超发。
- 当矩阵与softmax模板总量超过32字时，第二个模板等待前一个安全回收，没有扩容或删改指令。

开发中的C++构建错误与RF峰值测试假设错误保留在`shared-array-mixed-dev-*`，不作为通过证据。修正后的检查逐个追踪真实RF/SPM/ROM分区和服务所有者，而不是仅比较总峰值。

## 尚未完成的集成

默认`model_system::execute`仍是逐算子调用。后续新增的[整图就绪入口](mlx-ready-graph-execution.md)已接入四类后端、共同响应分发和按消费者完成管理的生命期；它以整个源算子完成作为依赖边界，不把独立算子或小图用例改称完整模型/CDC通过。生产者部分结果到消费者上下文的有界依赖事件、消费者驻留等待及资源预留仍需继续实现和验证无死锁条件。

模板内容/容量已经真实共享，但装载字数目前只是单列计数，`template_configuration_cycles_modeled=false`；不能把它当成已经建模的PE配置流量或推理性能。源参数/权重仍是测试输入预装载，不是CPU/DMA装载。本分支也没有修改RTL或重新标注主工作树中正在执行的完整模型版本。

复现时显式指定独立工作树的Python模块路径，并选新输出目录：

```bash
PYTHONPATH="$PWD/src:$PWD" .venv/bin/python -m scripts.verify_mlx_shared_array \
  --baseline-root /workspace/MLX_dev \
  --asan-binary build/mlx-shared-schedule-asan/shared-array-driver \
  --output artifacts/tagged/shared-array-NEW
```

ASan二进制由`simulator_ext/shared_schedule`的独立CMake构建生成，使用`-fsanitize=address,undefined -fno-omit-frame-pointer`。脚本只重新执行组件回归和对照，不运行完整模型。
