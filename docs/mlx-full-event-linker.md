# 完整模型窗口目录到 C++ 并发源流

本增量连接已经审计的窗口目录与现有 C++ 事件引擎，不修改 RTL，也不把 Python 链接耗时作为目标推理性能。

`scripts.link_mlx_model_event_graph` 检查完整窗口重建审计、程序与编译源码摘要、实际控制见证和窗口文件摘要，然后生成 v6 紧凑源流。缺少动态分支见证时拒绝链接，不用预期答案补齐控制路径。

链接保留全部源、外部父依赖、batch 窗口与原始流式配对；共享模板按机器字及阶段结构区分，块模式按局部循环事件内容去重。运行段保存重复次数与 PE 映射，重复窗口复用描述，不在 Python 中展开完整模型的所有逻辑块。C++ 仍执行全部动态工作，并处理有限驻留资源、完成槽、反压与并发。

## 独立审计与完整图运行增量

`scripts.verify_mlx_full_event_link` 不调用链接器，而是将运行段逐块对应到已经独立重建的原窗口，检查全部指令字段与循环、PE 序列、机器字及资源需求、阶段共享身份、父依赖、batch、原配对和硬件时序。只去除局部事件名字，不去除操作、次数或依赖。重复的同一窗口映射复用审计结果，不创建整模块对象。

完整 BERT 审计 `artifacts/tagged/bert-full-event-link-audit-002.json` 已通过：785 种窗口映射覆盖全部 3,838 个窗口，块和动态事件计数与上表一致。审计器新增正常与破坏输入检查后，相关联合回归为 99 项通过（`full-event-link-tests-002/results.xml`）。这仍是链接审计，不是执行结果。

`scripts.run_mlx_full_event_graph` 已启动 `artifacts/tagged/model-e2e/bert-full-event-graph-001` 的完整 C++ 事件运行。运行器复制二进制，记录依赖库、源码、审计和输入摘要；正常结束后再核对全部事件、源、配对与资源排空。实际进程终态以 `execution.json` 和进程查询共同核对，不能将状态文件单独当作存活证据。当前尚无完整事件运行终态，宿主看门狗为 172,800 秒；观察超时不触发重启。

## 最终读回边界

独立 `simulator_ext/readback_timing` C++ 工具按原生 `ready_graph.cc::readback` 的逐标量请求循环建模。若本次提交在 S，物理接收为 `align(S+1, accept_period)`，响应在接收后 `latency` 拍到达，消费后时钟再推进一拍；下一个元素从该时钟继续。对齐使用全局周期，不把每个输出张量重新置零。只支持已验证的无缓存、无 NACK 固定延迟物理端口。

这段串行读回是原生实现中“计算图和总线已经排空后”的行为，不串行化图内计算／搬运／调度。Python 仅从实际输出契约生成角色、元素数和字节宽度，时间推进由 C++ 实现。BERT 每个样本读取 start/end logits、mask 和 offsets 两列，合计 `5×序列长度` 次请求；Llama 读取各次 forward 的 logits 和 token。不能从文件写出时间或宿主后处理耗时推断硬件 CPU 周期。

`readback-timing-tests-002` 的 17 项检查通过：8 个 logits/token 原生小图、4 个 QA 原生小图的读回／合计周期一致，另有 5 项拒绝检查。覆盖接收周期 1/2/4 与不同延迟、QA 长度 28/64。它不是整模数值或 Chipyard 测试。

`scripts.complete_mlx_event_readback` 只接受完整事件运行的成功审计终态，核对同一程序与运行选项摘要，再用实际图周期作为读回起点；目前完整 BERT 未结束，入口已验证拒绝提前生成结果。新增实际小图贯通事件运行器、终态审计和读回入口后，总周期与原生相同，修改运行选项被拒绝；读回相关检查增至 18 项（`readback-timing-tests-003`）。这证明入口的小图成功路径，不是 BERT 后处理已经执行。最终可比较范围为“原生并发图＋其输出读回”，仍不含初始化、实际 Rocket CPU 或 QA 后处理的目标时序。正式误差需另行核对数值正确性、相同输入配置和完整原生终态。
