# C++ 按需事件解析与退休回收

此增量把外部块事件模式接入现有 C++ 调度器。端口、功能单元、源图准入和前端槽仍由同一调度器管理，**不是分别模拟各窗口再相加**。尚未把完整 BERT/Llama2 窗口目录接成整模执行。

## 执行规则

在 schema v6、`source_tick_order=true` 下，可使用 `event_patterns` 注册表和 `pattern_cache_bytes`。每块用 `event_pattern` 替代内嵌 events；注册项绑定文件路径、SHA-256、完整动态事件数和零工作标志。

块通过硬件容量准入检查后，C++ 才读取其事件文件并解析循环。模式中的局部事件 ID 加上块命名空间，执行状态互不混用。文件内容必须匹配摘要，解析后的工作数量、操作资源域和零工作语义也要匹配声明。未知、损坏或容量超限的模式拒绝执行；后继源未就绪时不会提前读取其文件。

块退休后，所有动态实例必须已完成；循环树释放，事件 ID 注销，执行槽进入可复用池。文件内容缓存采用 LRU。缓存是**宿主模拟器的元数据缓存**，不增加 MLX RF/SPM/ROM，也不替代目标模板编程周期。OpenSSL::Crypto 只用于文件摘要检查。

当前限制：块描述符与源窗口表仍预先保留，尚未实现按需生成整个块列表；缓存字节统计指序列化文件大小，不是 JSON 堆内存或进程 RSS。懒模式只接入源级依赖和块内顺序，不接受隐藏的跨块命名事件／block admission 依赖；streaming pair 需通过后续显式块事件协议接入，不能被删除或改称已验证。

## 验证结果

`lazy-event-regression-001`：342 项回归通过。新检查包括 8 个已登记真实数值依赖图对应的懒加载／预展开结果一致、私有控制／搬运、模板编程、缓存逐出、文件摘要／工作量／资源域错误拒绝，以及事件状态回收。

- 2,000 个块共 4,000 个叶定义，执行槽峰值为 4；同一文件读取一次。
- 1,667 个控制块共 1,000,200 个叶定义，全部执行，累计超过旧百万节点总上限；活跃节点与执行槽峰值均为 600，结束后排空。没有缩减实例或放宽活跃节点上限。
- `lazy-event-safety-002`：324 次 ASan/UBSan/LSan 重放通过（273 正常、51 预期拒绝），另核对文件摘要、LRU 缓存计数、活跃节点和执行槽峰值。第一轮的百万实例压力项触发了 60 秒宿主 watchdog；失败记录保留。后续使用 `-O1` 构建和 300 秒单项 watchdog，仍执行原完整用例、核对原结果，不减少工作量。

## 下一步

### 宿主 ROM 记录的后续回收

事件叶状态之外，旧实现还会保留所有退休的宿主 ROM 记录，后续查询反复扫描旧项。懒模式现在复用最后一个引用退休后的记录槽；物理 ROM 字地址、容量、内容和编程周期不变。

槽号不再代表创建先后，因此每次新驻留另分配单调 generation。模板写入仲裁仍按真实创建顺序，不能因为复用了较小槽号就抢到尚未编程完成的旧模板前面。回收前要求该记录已完全编程且所有引用释放，最终检查记录池排空。

`lazy-rom-regression-001` 的 344 项回归通过：2,000 个单上下文块产生 2,000 次模板驻留，但只分配 1 个宿主记录槽；另一用例在长模板编程中复用旧槽，完整结果与不复用的预展开路径一致。`lazy-rom-safety-001` 的 328 次安全重放通过（277 正常、51 预期拒绝），按实际模板引用区间重算记录峰值与驻留次数。

`bert-full-shape-lazy-pattern-002` 复查仍为 5,308,485 周期、724,992 个事件，原始／预展开／懒模式结果一致。本次单次宿主耗时分别约 32.33／33.49／34.59 秒，因此不据单次运行宣称速度提升；本项验收的是记录回收及目标时序不变。

将完整窗口目录按需实例化到源图，继续消除预先保留的块描述符，接入共享模板身份、真实 batch 地址、Llama2 分支见证、有限事件槽的流式块依赖及最终读回边界。六个原整模任务保持冻结、独立验收；Chipyard 整模仍最优先，GPU 其次，RTL/PPA 最后。
