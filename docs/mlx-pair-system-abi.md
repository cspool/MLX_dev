# 双算子块调度的真实 Rocket 系统接口

本增量把已验证的有界双算子事件接入真实 Rocket/RoCC/DCache 驱动的 C++ 模拟器，遵循“C/C++ 调度模拟器 → 系统集成 → RTL”的顺序。本次没有修改 Scala、SystemVerilog 或 PE/FU 电路。`mlx-pair-wire-v1` 是项目重建的执行模式接口，不是论文公开指令编码，也不等同于 CUDA 的线程或 warp ISA。

## 编译与接口

`system_sim/physical_device/pair_lowering.py::lower_pair` 复用已有矩阵、向量编译路径，输出一个固定 8832 字节描述符。它包含两个完整源算子的后端程序，不以一个代表性 tile 替代整个算子。

| 偏移 / 字节数 | 内容 |
| --- | --- |
| 0 / 256 | magic、version、生产者类型/长度、两个源 ID、事件预算、依赖输入掩码和保留字段 |
| 256 / 4288 | 矩阵或向量生产者；1088 字节矩阵描述符之后必须全部补零 |
| 4544 / 4288 | 同形状逐点向量消费者 |

magic 为 `0x4d4c585041493031`，version 为 1，生产者源 ID 必须小于消费者源 ID，事件预算为 1..32，输入掩码只能使用非零的低两位，flags 和保留字段必须为零。矩阵描述符从 batch 0 开始；运行器根据受检张量布局推导并执行全部广播 batch。

C++ 解码器再次检查依赖输入的物理地址、容量、类型、形状、步长和偏移确实绑定生产者输出。未标记的重叠依赖、两个输出重叠、消费者输出覆盖生产者仍需读取的数据、超出地址宽度或覆盖活动描述符均拒绝。编译及执行入口检查联合 RF/SPM/ROM 容量，不能把描述符元数据当作额外免费资源。

## 实际执行

`pair_runtime.cc` 中两个前端共享实际 RF/SPM/ROM、物理上下文、服务槽和总线响应分发。生产者块的全部输出写响应到达后才发布完成事件，下一边沿唤醒已驻留消费者；事件窗口和生产者资源预约提供背压及前进空间。矩阵所有 batch 完成、消费者结束、事件和存储/传输状态排空后，设备才报告成功。

描述符由真实系统总线逐拍读取。最后一个描述符响应之后的下一外部时钟边沿开始后端执行；每 PE 每周期最多装载一个本地模板字，并与新指令发射竞争。本地模板装载不替代前面的 CPU/cache 描述符传输。

`clocked_device` 对生产者和消费者的全部输出元素检查本次启动的已确认写入记录。错误或周期限额会进入失败/排空路径，不会被当作成功。复位后的启动使用新的事件 epoch。总线响应在外部边沿到达时，`PhysicalMux` 先更新时钟再检查新响应，仍保留已持有响应的稳定性和所有者检查。

## 已验收证据

- [pair-wire-001](../artifacts/tagged/pair-wire-001/report.json)：204 项回归通过，19 个正常/错误/恢复用例通过 ASan、UBSan 和泄漏检查；release 与检查构建的完整输出、事件和排空结果一致。错误注入用例预期失败，不要求其设备窗口 `done=true`。
- [pair-rocket-001](../artifacts/tagged/pair-rocket-001/report.json)：7 个真实 RV64 ELF 均退出 0，共 13 次双算子启动。包括 FP16/FP32 矩阵、8-batch 广播矩阵、mean 生产者，以及三步 token 回馈。CPU 检查两个完整输出，实际执行 argmax，读取所得 token 选择下一步输入；期望值仅用于检查。正常反馈为 1/2/3，扰动后为 2/3/0。
- [pair-system-build-002](../artifacts/tagged/pair-system-build-002/report.json)：新系统可执行文件的既有 45 节点图兼容性检查。构建 001 曾因 JsonCpp 头文件搜索路径缺失而失败；002 在构建参数补充 `pkg-config --cflags jsoncpp` 后通过，没有覆盖或改写失败记录。

验证入口为 `scripts/verify_mlx_pair_wire.py` 和 `scripts/verify_mlx_pair_system.py`。它们要求新的输出目录，绑定源文件、可执行文件、运行库及结果摘要；系统入口还校验 Chipyard 构建身份。复现时先按现有系统构建流程生成包含本增量的二进制，不能直接复用旧构建。

## 尚未完成

本次仅验收有限双算子模式及真实 CPU 接口。通用图的 CPU 任务表尚未自动合并这类算子对，也未实现双源完成标记和相应生命周期重排；原串行存储复用可能引入读写冲突，不能只替换描述符就宣称整图并行正确。

一般多生产者/多消费者 CDC、不同形状映射、RF/NoC 直传、新调度路径的完整模型端到端验证、所有目标模型、推理性能和 RTL 均未完成。主工作树正在运行的两项完整模型尝试继续使用其冻结版本，不包含本增量；本页证据不能替代它们的终态审计，也不能覆盖已有 GPU 数值容差失败。
