# Chipyard 宿主开销诊断（非模型性能实验）

为优先推进整模系统验收，先检查当前 Rocket 仿真运行过慢的宿主原因。两个完整尝试继续使用冻结的原二进制；本页所有回放均为新建诊断进程，不改变现有运行。

## 范围与发现

原生 MLX 后端和 Chipyard 生成代码均为 C/C++ 执行。`system_sim/host_diagnostics/gmon_preload.c` 仅在独立新进程中启用 glibc 的 PC 统计采样，不改硬件、不改变返回数据、调度、周期或缓存协议。没有向已运行的进程注入采样器。

在原 `llama2-rocket-full-001/preflight-plain` 输入上，新采样回放退出 0，完整 `device.json`、`memory.json` 与原记录逐字节相同：530,925 个设备周期，21 个窗口，23,361 次请求及响应。采样到的可执行文件内时间为 80.66 秒，其中 Verilator 生成的 `VTestHarness` 函数为 79.09 秒，`mlx::` 函数为 0.34 秒。分母是**可执行文件内的采样时间**，不包含动态库时间，不能当成整个进程时间占比或目标架构利用率。

这定位了本次小负载的宿主热点，**不是完整 Llama2 热点或性能结果**。完整运行的第 0 层大矩阵仍未全部完成，不根据该预检宣称整模加速。

当前构建日志在热点 C++ 编译命令末尾使用 `-Os`，覆盖前面的 `-O3`。`scripts/rebuild_mlx_chipyard_host.py` 将相同生成 C++ 复制到新目录，以单独目标、单独二进制试验 `OPT_FAST/GLOBAL/SLOW=-O3`。原生成代码、设备静态库、配置及断言保持不变；不重新生成或修改 RTL。

首次 `-O3` 预检退出 0，完整设备及内存报告与原预检一致（仅移除新加的只读 observer 元数据后比较）；同为 530,925 个设备周期。原构建的无采样同输入对照也退出 0、报告一致，宿主耗时 83.71 秒；`-O3` 为 91.03 秒，本次反而约慢 8.75%。这只是各一次的宿主诊断，不是统计稳健的性能基准；**本次试验没有获得加速，因此不采用该构建替换完整运行**。没有以采样运行的耗时充当优化基线。

## 工具与边界

- `scripts/profile_mlx_chipyard_host.py` 绑定原执行二进制、ELF、输入、profile 和动态库摘要，复制独占二进制，只修改诊断周期上限和报告输出目录；无采样与带采样均可使用。
- 诊断脚本允许按明确周期上限执行完整原图的前缀。限额退出和部分报告仍是诊断，不是完成推理，也不用于缩小模型外推。
- `scripts/rebuild_mlx_chipyard_host.py` 保留原生成 C++、外部库/构建文件摘要、独立 make 目标、dry-run 与编译日志。完整报告等价后，仍需更充分系统验证才能将宿主优化接入新的整模尝试。
- 采样器要求显式绝对输出路径、拒绝覆盖已有元数据、拒绝占用已有 SIGPROF/ITIMER_PROF。只记录 PC 直方图，没有调用图；时间聚类不包含共享库。

18 项工具检查通过，覆盖真实采样/输出一致、输出保护、计时分母、严格周期上限和独立构建目标。测试不修改 MLX 后端，不构成整模验收。

运行记录位于开发工作树：

- `artifacts/tagged/chipyard-host-profile-preflight-VCuP02`：原二进制带采样预检，原始 gmon 与 gprof。
- `artifacts/tagged/chipyard-host-o3-001`：独立编译日志、输入摘要和诊断二进制。
- `artifacts/tagged/chipyard-host-o3-preflight-001`：`-O3` 无采样预检及等价核对。
- `artifacts/tagged/chipyard-host-baseline-preflight-001`：原二进制无采样对照。

这些记录的退出码、源身份和报告字段均须独立检查。宿主加速不等于 MLX 架构加速；无论诊断是否成功，GPU 新实验仍等待 P0 验收，RTL/PPA 最后。
