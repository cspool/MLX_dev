# 有界块完成事件与双算子流水

本实现位于独立分支`mlx-shared-array-v1`，采用新增的项目重建控制profile `mlx-bounded-pair-events-v1`，不是论文公开ISA的直接复刻，也不是CUDA/SIMT线程模型。

## 编译路径

`model_block_pipeline.compile_block_pipelines`在已有完整数值程序上增加调度计划，保留全部nodes、assets、outputs及原有后端程序。首版选择不相交的闭合双算子组：矩阵或向量生产者的输出只有一个消费者，消费者为同形状的逐点向量算子，其他输入在组启动前已经就绪。

编译器从实际形状推导矩阵2×16 tile、向量16-element块、归约输出行和矩阵batch偏移，生成生产者块到消费者输入的映射。C++入口再次根据原节点核对映射、块数、源身份及RF/SPM/ROM需求；不能仅相信额外JSON描述符。

不满足结构或资源条件的组合保留原来的整算子依赖执行，数值仍进入已经实现的MLX后端，不调用功能算子/GPU回退，也不删除节点。首版不支持任意多生产者、多消费者、形状重映射或一般CDC自动分解。

## 执行规则

- 消费者可以在数据未就绪时先驻留，实际占用RF/SPM/ROM和物理上下文。`wait_event`期间不启动输入DMA或运算，其他就绪上下文仍可执行。
- 生产者只有在该块全部输出的真实写响应完成后才产生事件；事件下一边沿才可见。消费者逐块检查所有所需生产者块，不把发射或物理请求接受当作完成。
- 完成窗口最多使用32个记录。已连续完成的历史用一个前沿计数器表示，乱序/在途部分保留在有界窗口中；窗口满时限制新的生产者块准入。事件记录可以复用，但epoch、block和lease必须匹配，过期/重复/未准入完成会拒绝。
- 完成历史压缩不等于释放数据：生产者输出的物理Tensor及消费者pin保留到实际消费结束。当前交接经过同一个受检物理内存，不是已实现的RF直传或NoC xfer。

为给生产者保留前进空间，每PE对组内生产者和消费者各最多准入一个上下文；消费者的全局SPM占用不得挤掉一个生产者帧。组的联合RF/SPM/ROM需求必须落在16向量、128向量和32指令字约束内。当前一次只保留一个此类组的PE资源域，组结束之前不启动其他PE算子；CPU叶控制及搬运仍通过共同物理端口运行。这是明确的保守预约，不声称一般图的无死锁问题已经解决。

新增完成窗口属于有界控制元数据，不能隐藏为免费RF/SPM容量。其RTL存储实现、配置传输和物理成本尚未验证。

## 已有证据

[block-pipeline-002](../artifacts/tagged/block-pipeline-002/report.json)记录212项回归及20个ASan/UBSan/LSan流水执行重放，数值、事件、周期和资源结果与release一致。001保留为增加非法存储需求前置检查之前的历史版本。

用例包括：

- 消费者先驻留并等待，在生产者整算子完成前实际发射；与只等待完整生产者的同资源对照相比，算量和数值不变。
- 1/2/32记录窗口、不对齐尾块、16-PE FP32资源预约、超过256个消费者块和300次单记录复用。
- 矩阵、向量及mean行生产者，矩阵8个batch的事件偏移，以及三步生成/cache图的不同epoch。
- 错误映射、块数、资源预约、窗口容量、旧epoch和重复/未准入完成的拒绝。
- 零SPM、超大SPM或RF需求在预约算术之前拒绝，避免坏描述符触发除零或容量计算溢出。

完整公开Llama2程序仍有6181个原始节点，新增计划选择873个闭合双算子组；去掉新调度计划后，整个数值程序与原输入一致。新入口只进行了1周期限额启动核对，预期退出1，没有完整推理结果，不能把873个编译分组改称已在完整模型中执行通过。

## 使用

```bash
PYTHONPATH="$PWD/src:$PWD" .venv/bin/python -m scripts.compile_mlx_block_pipeline \
  --program program.json --output pipeline-program-NEW.json --event-slots 32
```

给`mlx-ready-graph`的options显式设置`"tile_pipeline": true`，同时保持`overlap=true`和至少两个活动源描述符。`pipeline_whole_source_barrier=true`只用于同资源对照：消费者仍驻留并保留相同预约，但等待生产者全部块完成。

事件profile尚未封装进新的真实CPU/RoCC系统ABI；模板装载时序、一般CDC、完整模型端到端、所有目标模型与输入、系统性能及RTL仍未完成。主工作树的两项完整运行继续使用原有冻结版本，不重新标为已经使用本实现。
