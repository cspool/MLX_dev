# GELU erf 形式的 C++ 原语路径

2026-09-09验收更新：[392项回归与14次安全重放](../artifacts/tagged/gelu-publication-001/manifest.json)通过，其中7个正常执行、7个预期拒绝。完整`[1,28,3072]`物理算子使用原尺寸，安全重跑的输出/事件/周期与release一致；首轮1200秒宿主watchdog失败保留，第二轮仅将宿主上限改为3600秒。完整6181节点Llama2编译产物不变。此组件验收不是完整BERT、Rocket或作者hybrid通过。

本增量实现 `aten.gelu.default(approximate="none")` 的编译路径。它使用现有乘加、NEG、MAX选择、DIV、EXP及精度转换原语，没有添加假定的erf硬件单元，不将该算子静默替换成tanh形式。Python只生成IR和做参考/审计，模型中的中间值由C++实际计算、写入和读取。

[PyTorch GELU定义](https://docs.pytorch.org/docs/2.14/generated/torch.nn.GELU.html)区分默认的高斯CDF形式与显式tanh选项；这里保持前者的数学目标，但以明确登记、单独验证误差的FP32近似执行，不声称复现框架内核的逐位算法。

## 公式来源与数值合约

系数来自[Abramowitz–Stegun原书第299页、式7.1.26](https://personal.math.ubc.ca/~cbm/aands/page_299.htm)，书的出处另见[NIST介绍](https://www.nist.gov/mathematics-statistics/handbook-mathematical-functions-abramowitz-and-stegun)。已查看该页扫描件并核对系数，而非仅依据二手代码。

对非负参数，采用 `t=1/(1+p*z)`、五项多项式乘 `exp(-z*z)` 的erf近似，`p=0.3275911`，系数为 `0.254829592, -0.284496736, 1.421413741, -1.453152027, 1.061405429`。原书给出的实数公式误差界为 `1.5e-7`；它**不是**本项目FP32计算链或最终FP16输出的误差界，舍入、符号恢复、尾部处理及输出转换必须另外验证。

项目模式为 `mlx-gelu-erf-as7126-fp32-v1`：先显式升至FP32，按固定Horner顺序计算erf形式的GELU，最后按原输出dtype转换。仅erf求值支路把x限制到[-8,8]；外部 `x/2` 仍使用实际原输入，不能把大正输入的输出截成8。符号支路使用已有MAX/DIV和固定最小正规FP32量，避免零输入处除以零。系数、连接关系、尾部范围和dtype均由C++再次核对。

这里的MAX是已有opcode的“a<b时取b，否则取a”，不是新增的完整ATen maximum语义。`mlx.primitive.maximum/div`为编译器内部IR符号，不能作为真实模型捕获算子冒充覆盖。EXP/DIV仍使用原有4-lane SFU分组；每个模板不超过32word，RF/SPM和在途容量不扩张。

FP32 GELU为31个原语步骤，FP16另有输入/输出转换。当前是未融合降级，临时Tensor占用模型物理RAM，所有访存和周期成本真实计入；不声称融合kernel的效率。原始源与降级步骤通过v3 source_groups分别计数。

## 正确性检查的边界

测试中的两个组件数学误差上限在执行前固定：FP32绝对误差3e-6、FP16绝对误差2e-3。它们不替换任何模型或GPU验收阈值。参考采用独立控制的FP32原语顺序，并明确共享原子expf；另使用稳定的FP64 `x/2 * erfc(-x/sqrt(2))` 数学参考检查误差。

数值范围包括全部63,488个有限FP16编码、稠密[-10,10]区间和固定seed的有限FP32位模式采样。FP32采样不是全部FP32输入的穷举或统一误差证明；原书的实数界也不能代替该证明。非有限输入/输出不用于放行完整模型数值门槛。

必须保留框架差异：在这组FP32样本中，目标与声明原语顺序逐位一致、数学误差在预设界内，但框架对70个极大有限输入返回非有限值。只报告其余有限结果上的误差并不等于整体框架比较通过；报告将这一框架比较保留为false，不排除失败后宣称全面一致。
