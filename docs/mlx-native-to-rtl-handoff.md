# M3 → M4：原生模型到功能 RTL 的交接

状态：M3 已通过 `artifacts/tagged/stage2-acceptance/certificate.json`。M4 已开始，控制/共享 RF 前端组件进展见[RTL 实施状态](mlx-tagged-rtl-progress.md)；本文件中的完整功能 RTL 和 PPA 要求仍未全部完成。

## 实现前保留的基线

- 第一阶段：`simulator_ext/tagged/` 的 C++ 合约、数值执行和周期模型，以及 `tests/test_tagged_scheduler.py` 中 T1–T12 的组件要求。
- 第二阶段：同一 C++ 模型的实际 Rocket/RoCC/DMA 执行与系统证书；证书为 `system_stage_passed`，20 项回归，9 次真实 ELF。
- 程序接口：`Program.image()` 的机器字、四字描述符与 I/O 掩码，见 [ISA](mlx-native-isa.md) 和[系统合约](mlx-native-system-contract.md)。不能为了适配旧 RTL 而截断 block/layer/iteration 身份或移除依赖。

开始 RTL 工作前核对两阶段证书的源码摘要和系统构建身份；源码或构建不对应时先复验。旧 `rtl/mlx/` 与旧系统后端保留为历史基线，不将它们的既有通过结果计入新模型的 M4 验收。

## 需要落实为电路的状态与约束

| C++ 已验证行为 | RTL 必须实现的对应内容 |
|---|---|
| 波次准入、逻辑块排序和物理槽复用 | 有限描述符/配置存储、资源准入、上下文初始化与排空回收；不能为每个逻辑层永久分配一套 PE |
| 每块独立 frontier、iteration、inflight、valid | 驻留上下文状态库；逻辑 ID 与 slot 分离，完成反馈检查 epoch/iteration/PC |
| 每 PE 选择 ready 且资源可用的候选 | 真正驱动取指和操作数选择的仲裁输出；被阻塞候选不能冻结其他合法候选 |
| 每 PE 16 个向量寄存器、一个写端口 | 按上下文 RF base 分区与生命期复用；不能给每个 slot 各增配 16 个寄存器 |
| 独立在途操作 | compute、SPM、xfer 各自保持请求身份和数据；发射不等于完成，FU/数据返回才推进对应上下文 |
| 一个 compute 在途、一个全局 SPM 请求、一个向量/路由器 | 按模型的有界容量实现，不以无界队列或额外端口换取一致性；容量扩展另立实验 |
| 目的输入 credit、带迭代身份的 xfer | 防止旧迭代写入新实例，以及未来迭代数据堵住当前必要的通信 |
| 满路由缓冲允许同周期出/入队 | 有界路由仲裁和合法交换；若采用不同实现时序，先解释对应模型差异并测量其影响 |

当前周期完成的数据在下一周期才能参与候选发射。单 PE 一个 RF 写端口的优先级与争用、每 PE 一个 issue、compute II，以及串行/重叠两种策略都需要明确对应关系。若 RTL 的装载/准入或流水线时序与组件抽象不同，保留实际总周期并解释差异；不能删除控制开销来伪造逐周期一致。

## 不可直接复用的数值假设

旧 `mlx_fp16.sv` 的乘加存在截断与 subnormal 简化，EXP 仅对少数输入使用小查表并为其他值给出近似默认值。旧 `mlx_fu.sv` 的高精度路径也不能作为当前 FP16 ISA 的数值证明。它们不满足新 C++ 模型的已登记数值合约，不能仅把新的调度器接到旧 FU 后就宣布 M4 完成。

需要验证 FP16 舍入、非融合 MAC-step、MAX、除法、EXP 和 shuffle 的实际支持范围。运算不能调用 C++ DPI 或主机数学库来冒充已实现的功能 RTL；测试数据或期望结果也不能进入执行数据通路。受限 lane 语义仍按项目 profile 标注，不能由物理单元宽度自行推断成论文完整 ISA。

## 实现与验收次序

1. 上下文状态、准入/退休、候选选择和完成归属；建立可控延迟、反压、错误 epoch/iteration、槽位复用的组件回归。
2. 与合约一致的数值单元、RF、SPM 以及有限网络；组成真正执行公共程序的多 PE、多上下文 RTL。
3. 用同一编译产物和输入复用 T1–T12、四个登记负载、两 PE 折叠对照与非法编码检查。单个仲裁器测试不能替代完整数据执行。
4. 接入系统后端，在真实 ELF 中比较功能、事件与系统计数，分别标记 native C++ 和功能 RTL 的证据。
5. 对实际新增电路综合并报告资源、面积/时序及可获得的功耗证据。抽象 cell count 或行为模型速度不能冒充完整 PPA，也不能沿用旧 RTL 的 PPA 当作新实现结果。

第一、二阶段已通过只解除实施顺序上的限制，不减免上述 M4 条件。可选 M5 扩展仍按先模型、后系统、再 RTL 的顺序处理。
