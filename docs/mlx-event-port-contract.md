# 事件端口契约与完整矩阵窗口 lowering

本次补齐 C++ 事件模型的共享端口约束，并从真实矩阵微程序生成完整窗口的循环事件。**不是完整 Llama2/BERT 事件运行，也还没有整模性能误差。** 未修改任何正在运行的端到端或 Chipyard 版本。

## schema v3 的约束

- DMA 请求不占 PE 指令发射口；PE 指令先参与本边沿的发射仲裁，DMA 写请求再竞争 SPM 口。
- SPM 读/写发射、SPM 写完成、DMA 读响应及 DMA 写发射共用全局 SPM 口。SPM 读、计算和 SFU 完成竞争对应 PE 的 RF 写回口。
- 服务单元在实际完成并经过释放边界前保持占用。写回或响应受阻会延迟完成和后继可见性，不能仅按名义延迟提前释放。
- 显式设置 SPM、写回、DMA 请求/响应周期和计算发射间隔；日历只跳至真实可推进的边界，不靠周期唤醒掩盖死锁。
- 每个源每边沿最多准入一个块，保留该源的块顺序；新上下文从下一边沿开始发射。
- `predicate_skip` 只消耗一个发射机会，没有 FU 工作、SPM 访问或 RF 写回；完成同边沿提交，下一边沿可推进。

v1/v2 既有契约不变。v3 采用全局完成优先顺序（SPM、DMA、计算/SFU）并保留并发。**它还不等同于原生多源执行器逐源 tick 的完整顺序**；同源矩阵窗口的对齐不能直接推广为跨算子配对或整图已经一致。

## 从实际微程序生成完整窗口

`src/mlxsim/model_matrix_events.py` 检查 canonical `mlx-matrix-f32-kasc-v1` 程序、维度、dtype、bias 和并发选项；依据真实机器字识别行谓词和指令类型。保留初始化、每个 K 分块的全部 A/B 标量搬运、完整 body 循环、bias、尾部和输出写回。K=0、奇数行、非整 SIMD 列及 K 跨 64 边界均有对应路径。

所有块固定映射到原生规则指定的 PE，使用程序实际 RF/SPM/ROM需求。只产生计时事件，不读取参考输出、不执行 Tensor 数值、不由原生耗时反推事件延迟。当前入口是单个完整矩阵窗口、固定延迟内存端点及未计时模板装载；不是多 batch/多源完整模型适配器，也不替代 Chipyard 缓存。

编译入口：`python -m scripts.compile_mlx_matrix_events --job <完整矩阵窗口.json> --output <新目录>`。

## 对齐证据

95 项回归通过；94 个 ASan/UBSan/LSan 重放通过，其中 67 正常、27 预期拒绝。22 个窗口在原生 C++ 数值执行与事件执行中具有相同的周期、DMA 字节、有效 MAC 数、谓词数及在途资源计数。原生输出另与逐 K FP32 参考逐位核对；独立重放工具重新执行两条路径并复核原始输出和完整报告。

覆盖 FP16/FP32、有无 bias、K=0、尾部行列、K=65、多个 PE/上下文，以及非默认 SPM/写回/DMA 周期和计算间隔。这些窗口的周期差为零，**不是整模误差为零，也不是性能参数已校准的证明**。

计数分开保留：

- `*_busy_*` 为服务保留区间，包含完成后到下一释放边界。
- v3 的 `*_inflight_*` 为尚未实际完成的占用，与原生窗口的在途计数对应。
- 端口等待、端口使用次数、有效 MAC/lane 和搬运字节另列，不能把保留时间或驻留上下文数直接当成有效并发效率。

仍需接入向量、独立搬运、控制、完整 batch/源图和逐实例块间事件；再对齐原生跨源仲裁及模板装载，完成整模比较。六个现有完整运行继续独立验收，GPU 与 RTL/PPA 顺序不变。
