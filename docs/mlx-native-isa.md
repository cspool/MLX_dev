# 从 MLX 硬件约束推导执行模式与 ISA

更新：2026-09-07。状态：系统集成所使用的公开重建 ISA 子集；编码不是论文作者公布的编码。

后续范围澄清：本页具体编码／舍入／上下文描述属于早期 `tagged_program.py` 与 `simulator_ext/tagged` profile，不是当前完整模型 matrix/vector/memory/control 四后端的统一 ISA。请结合[当前指令集与空间调度联合契约](mlx-isa-spatial-scheduling-contract.md)使用；不得将两套 MAC 数值语义、lane 规则或资源配置混用。本页历史内容保留，不据此改写正在运行的模型配置。

## 1. 设计依据与层次

ISA 在这里定义为硬件能够承载、并由编译器显式表达的执行模式集合。先确定数据驻留、依赖、并行和资源边界，再确定指令语义及编码。不能因为模拟器容易解释某个字段，就把它当成论文硬件天然支持的功能。

证据来自[本地论文](../MLX%20Multi-Layer%20Execution%20for%20Structured%20LLM%20Workload%20Acceleration%20on%20Spatial%20Architectures/MLX%20Multi-Layer%20Execution%20for%20Structured%20LLM%20Workload%20Acceleration%20on%20Spatial%20Architectures.md) IV-B/IV-C/IV-D、V-A/V-B/V-C 和 VI-A。下文用三种类别标明来源：

- **论文语义**：文字或图示明确支持的执行方式。
- **实现推测**：为可执行、可检查的重建补充的语义；需要独立验证。
- **编码选择**：本项目的操作码、位宽、地址与 ABI，不能反推作者原始实现。

必须区分三个层次：RISC-V host 的命令协议、PE 执行 ISA、tagged block/CDC 配置描述符。逻辑循环和层依赖属于执行模式，但不必全部成为独立的逐条 opcode；描述符可以承载它们。

设计顺序是：**论文架构与约束 → 可支持的执行模式及可观察语义 → 编译映射与合法性检查 → 指令/描述符编码 → C++ 系统装载与执行验证 → RTL**。这里先确定的是架构契约，不是先画电路再补模拟器；必要的语义修改也应先返回独立 C++ 模型验证，再更新系统接口。

还要区分 ISA 语义与微架构时序：数据类型、寻址方式、依赖可见性、循环和完成条件属于程序契约；具体 FU latency、仲裁优先级、每周期发射数和缓存延迟属于所选模型配置，通常不应固化为操作码。容量可作为目标 profile 与编译准入约束，而不是要求程序假定无限上下文。比如四分之一宽度的超越函数单元只说明物理并行能力，并不能单凭这一点确定其他 lane 的架构结果；当前受限 lane 语义必须作为重建 profile 单独声明。

## 2. 由硬件约束得到的执行模式

| 架构事实或约束 | 可固化的执行模式 | ISA/描述符表达 | 来源与当前范围 |
|---|---|---|---|
| 每 PE 有本地 RF 与 SIMD FU | 对本地向量操作数执行算术并写回 | 向量 ADD/MUL/MAC/MAX、寄存器源/目的 | 论文支持异构算术；具体操作码和精确舍入是编码选择/实现推测 |
| 超越函数单元仅为 SIMD 宽度的四分之一 | 受限 lane 范围内执行 EXP/DIV 等操作 | 操作类型与数值/lane profile | 四分之一宽度是论文语义；其余 lane 保持输入是本项目选择，不能冒充已知硬件行为 |
| SPM 与计算解耦 | SPM 向量读入 RF，RF 向量写回 SPM | LOAD/STORE、SPM 槽与迭代 stride | 独立 load/store 是论文语义；当前实现连续向量访问，未实现论文的完整行/列双访问模式 |
| 数据沿固定空间拓扑传递 | 将本地向量显式传给下游 PE，并写入目的 RF | XFER、残余方向/距离、目的寄存器、端点绑定 | hop 编码与目的 RF 是论文语义；当前绑定到逻辑描述符是重建选择 |
| 静态块内顺序、有限活跃层 | 一个块保持 frontier，多个块按就绪/资源仲裁 | tagged-block 模板、逻辑层、物理槽、ready 与 inflight 状态 | 论文语义；每块至多一条在途指令是首版保守实现推测 |
| 短模板加循环次数重复执行 | 重放同一局部更新模板，推进 CDC 实例 | 模板起点/长度、trip count、iteration | 论文语义；当前循环次数放在描述符，不增加通用分支 ISA |
| 有限 RF、程序存储和通信缓冲 | 资源合法时驻留/发射，不足时等待或拒绝 | 资源需求、窗口、准入规则与明确的完成条件 | 资源有界是论文语义；4 个上下文、16 个向量寄存器及单缓冲网络是当前模型配置 |

论文明确的完整设计点是 SIMD32、4×4 PE、每 PE 32 条指令；SIMD8 是 reduced 设计点。测试使用的 SIMD4、较少 PE 等配置仅用于机制检查，不作为论文硬件配置的证据。

## 3. 当前可执行的 PE 指令子集

这些语义由[程序合约](../src/mlxsim/tagged_program.py)、[C++ 程序验证](../simulator_ext/tagged/program.cc)与[数值实现](../simulator_ext/tagged/fp16.cc)共同约束。

| 操作码 | 当前名字 | 执行语义 | 资源与完成条件 |
|---:|---|---|---|
| 0 | LOAD | `RF[dst] ← SPM[base + iteration × stride]`，读取一个向量 | SPM 请求获得服务，数据返回并写入 RF 后完成 |
| 1 | STORE | `SPM[base + iteration × stride] ← RF[src]` | 写入按存储协议提交后完成 |
| 2 | FMA / MAC-step | `RN16(RN16(a × b) + c)` | 占用 compute 服务，结果写回后完成；这是逐步舍入，不宣称 IEEE fused FMA |
| 3 | ADD | FP16 向量加法 | compute/FU 的 latency、II 与 RF 写端口约束 |
| 4 | MAX | FP16 向量逐元素最大值 | 同上；跨 lane 或跨向量归约仍须由指令模板构造 |
| 5 | EXP | 当前 profile 的前 `SIMD/4` lane 做指数运算 | 受限算术服务；其余 lane 保持源值属于当前 profile |
| 6 | DIV | 当前 profile 的前 `SIMD/4` lane 做除法 | 同上；不能将其视为全 SIMD 吞吐的除法单元 |
| 7 | SHUFFLE | 当前仅支持 `lane → lane xor 1` | 这是已实现的邻接交换子集，不是论文完整向量置换单元 |
| 8 | XFER | 按静态端点与合法路由将向量送入目标块的输入寄存器 | 目标迭代匹配、输入有接收空间；目的数据可见后通知发送者完成 |
| 9 | MUL | FP16 向量乘法 | compute/FU 的 latency、II 与 RF 写端口约束 |

不同块等待 load、执行 compute 和推进 xfer，可以时间重叠。指令名字中出现独立流水线，并不自动保证每周期同时发射四条指令；当前模型每 PE 只有一个 issue 端口和一个 RF 写端口。该限制必须进入性能模拟。

LOAD/STORE 中的 iteration stride 是向量槽步长，不能当成论文 row/column SPM 模式的替代证明。复杂 FFT 通过实/虚向量和算术模板构造，当前没有“一个 opcode 自动完成任意 FFT/矩阵乘”的隐藏计算。

## 4. tagged block 与依赖不是 GPU 线程的翻版

每个块的描述符包含逻辑块 ID、逻辑层、PE、模板起点/长度、资源需求与 trip count。执行实例还包含物理槽、epoch、iteration 和 frontier。物理槽可以复用，逻辑身份不能截断为当前槽编号。

块内采用编译后静态顺序，硬件模型负责块间的就绪与资源仲裁。计算结果到达、SPM 返回和显式传输交付产生可观测事件；这些事件与当前执行实例绑定。优先级用于选择合法候选，不能代替依赖检查。

论文 V-B 的 Eq. 3 对 CDC 层要求层内或相邻层通信。当前通用模拟器接受更宽的无环前向图；组合算子还包含跨多个逻辑层保留的值。因此当前 profile 不能直接声称完全满足论文的 adjacent-layer CDC 约束。要发布严格论文 profile，需要把此类值明确归类为 tile-local state，或插入逐层 forwarding/显式组件边界，并检查所有边；不能靠忽略边或改变 layer 标签通过检查。

当前 XFER 机器字中的目标描述符索引用于编译/装载时绑定接收上下文，是实现推测。它不意味着 NoC 路由器具有通用动态映射表；转发仍按静态坐标/残余距离推进。将来 RTL 可以将该绑定下沉为 tag/路由类元数据，但必须保留相同的可观察依赖语义。

## 5. 当前编码与系统 ABI

### PE 机器字

64-bit 编码是本项目选择：opcode `[63:60]`、保留字段 `[59:56]`、pipeline `[55:54]`、目的 RF `[53:50]`、三个源 RF `[49:38]`、有符号 dx/dy `[37:28]`、SPM 向量槽 `[27:20]`。

低 20 bit 按指令解释：LOAD/STORE 的 `[19:12]` 是有符号迭代 stride；XFER 的 `[19:4]` 是目标描述符索引。未使用字段必须为零。pipeline、路由和端点字段必须与 opcode/静态映射一致；解码器通过规范重编码检查，不应悄悄忽略非法位。

### 描述符与装载

程序镜像头使用 `0x4d4c580200000001`，包含描述符数量和目标几何。每个描述符四个 64-bit 字，分别携带逻辑身份、模板/资源信息、循环次数和保留字。PE 程序存储按 32-word 步长定位。镜像格式和 PE 指令编码是不同的版本化对象。

### RISC-V 主机协议

`config / launch / wait / status` 是主机扩展命令协议，不是上述 PE 算术 ISA。论文只明确需要紧凑配置/访存协调命令；选择 `custom0`、funct 数值和状态索引属于本项目实现。

当前 C++ 系统适配器使用四个额外配置字 `0x1e00..0x1e03` 描述输入/输出 SPM 槽位掩码。主机缓冲区按槽位递增顺序紧密打包。launch 提供真实输入/输出地址；输入必须通过模拟内存请求读取，不能取用编译时 golden 代替。wait 以实际完成为依据，status 标明 ABI、错误及周期计数。

独立模型计数与系统总周期分开。配置解码、输入 DMA、计算、输出 DMA 的划分是系统模型合约；未来 RTL 的实际控制开销与此不同，需要解释和测量，不能反向调整 ISA 语义来拟合性能。

## 6. 系统集成的 ISA 验证门槛

1. 每种可执行操作都能关联到上述资源支持及完成条件；未实现模式明确拒绝或列为未覆盖。
2. 主机协议、镜像、描述符、PE 机器字分别验证，不能因一个 ABI magic 匹配就跳过其余合法性检查。
3. 编译产物在 C++ 和系统装载后保持指令、循环、端点和数值语义一致。
4. 真实访存响应及依赖事件驱动完成；反压、错版本、非法位域、错误路由和资源超量有可观察结果。
5. 不将本子集的通过声明为完整论文 ISA 的通过。完整 row/column SPM、一般 shuffle、严格相邻层 profile 和高精度路径仍须分别设计、实现与验证。

每项新增或修正的执行模式应记录：论文位置、硬件支持与容量约束、输入/输出与数值规则、依赖和完成条件、编译 lowering、解码合法性、正例与拒绝用例。缺少证据的部分允许提出可检验的推测，但不能因已经写入模拟器或分配了 opcode 就视为论文已确认。参考 GPGPU 时也使用同一要求：借鉴驻留准入、上下文选择、资源反馈等职责，不自动加入独立线程 PC、分支重汇合或其他没有 MLX 架构支持的执行模式。

后续 RTL 从已验证的执行模式实现电路；ISA 中新增模式也必须同时补上对应资源、编译和模型验证，不能仅增加一个操作码。
