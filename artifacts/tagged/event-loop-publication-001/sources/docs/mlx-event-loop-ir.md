# C++ 事件循环 IR：完整实例数与按需遍历

本增量补齐完整微程序事件表示的循环基础，不是完整模型事件接入，也没有形成 MLX 两模型性能误差。

`mlx_event_schedule_v2` 接受嵌套 `{"repeat": N, "body": [...]}`。C++ 只存储有界循环树和叶事件，通过每个驻留块的逻辑位置查找下一实例；每一次实际事件仍参与依赖、资源仲裁、完成和计数。没有裁剪波次、按层数外推、把重复次数当作表容量或省略循环中的搬运。

沿用 v1 的有限 RF/SPM/ROM、模板加载、调度策略与服务时序。此次没有把 v1 的抽象服务模型改称原生矩阵调度器：DMA 发射端口、写回竞争、谓词指令、准入节拍等原生对齐工作仍待完成。v1 已有回归保持通过。

## 明确的语义

- 同一块的指令顺序由循环流隐式规定，完成的下一边沿才能推进；v2 不接受同块命名依赖，以免把本次迭代与最后一次迭代混淆。
- 跨块命名依赖表示等待该叶事件的**最后一个实例**完成并可见；trace 同时记录叶 ID 和零起始实例序号。需要逐迭代生产者/消费者通信时，后续还须实现显式实例化的块间事件，不能用此终结屏障冒充流水传递。
- 块退休发生在其全部动态事件结束之后；资源释放和其他块并发不因循环而改变。
- 循环次数须为正整数；深度最多 16、v2 树元数据最多 100 万项；检查次数、时间与工作计数溢出。非法程序不会产生成功报告。

## 验证

55 项回归通过，58 个 ASan/UBSan/LSan 重放通过（37 个正常、21 个预期拒绝）。涵盖两种调度策略、同 PE/不同 PE、模板加载、共享 DMA 竞争、嵌套循环和跨块最后实例依赖；紧凑表示与完全展开表示的周期、完整 trace、资源积分和工作计数相同。

一个组件用 2 个叶事件、3 个树节点表达 10,000 次 DMA/计算循环，实际完成 20,000 个事件、40,000 bytes 声明搬运、140,000 个目标周期。十亿次循环的限额诊断也能直接进入执行并按周期预算拒绝，无需分配十亿份描述符。这些是组件结果，不是整模性能或实际 Tensor 执行。
